# Сайт преподавателя физики и математики

## Запуск

Нужны JDK 17+, Maven 3.8+ и Node.js 20+. Команды ниже рассчитаны на bash/zsh
(macOS/Linux). Каждый терминал начинайте из корня проекта.

```bash
# Бэкенд на http://localhost:8080, первый терминал
cd backend
ADMIN_PASSWORD=admin123 \
  CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173 \
  mvn spring-boot:run

# Фронтенд на http://localhost:5173, второй терминал из корня проекта
cd frontend
npm ci
npm run dev
```

Команда `mvn spring-boot:run` по умолчанию включает профиль `dev`: база H2 работает в памяти,
отдельно устанавливать её не нужно. При перезапуске бэкенда все изменения в этой базе теряются,
а демоданные создаются заново. Консоль: http://localhost:8080/h2-console
(JDBC URL `jdbc:h2:mem:tutorsite`, пользователь `sa`, пароль пустой).

Vite проксирует `/api` на бэкенд. Прокси не отменяет проверку CORS: без настройки `CORS_ORIGINS`
разрешены только `http://localhost:5173` и `http://localhost:3000`. Команда выше дополнительно
разрешает `http://127.0.0.1:5173`, чтобы вход и регистрация работали по обоим локальным адресам.
Если Vite выбрал другой порт, добавьте его адрес в `CORS_ORIGINS` и перезапустите бэкенд.

Откройте http://localhost:5173/login. После приведённого выше запуска доступны три демоаккаунта:

| Роль | Логин | Пароль  |
|---|---|---------|
| Админ | ney4s@tutorsite.local | admin123 |
| Ученик | student@tutorsite.local | student |
| Ученик | petrova@tutorsite.local | student |

`admin123` — только пример для локальной проверки: он передаётся переменной окружения,
а не задан в коде. Без `ADMIN_PASSWORD` администратор создаётся с пустым паролем,
и форма входа не позволит авторизоваться. Для сервера задайте отдельный сложный пароль.
Администратор после входа попадает в `/admin/students`, ученик — в `/cabinet`.

### На PostgreSQL

В корне проекта создайте `.env` из `.env.example`, если его ещё нет, и заполните
`ADMIN_PASSWORD`, `JWT_SECRET` и `DB_PASSWORD`. Генерация ключа описана ниже.
Compose использует этот файл автоматически, а Maven — нет, поэтому для Maven переменные
нужно явно загрузить в окружение. Загружайте только свой проверенный `.env`.

```bash
docker compose up -d postgres

# Дождитесь готовности PostgreSQL, затем запустите бэкенд
(
  set -a
  . ./.env
  set +a
  export DB_PORT="${DB_PORT_HOST:-5432}"
  cd backend
  mvn spring-boot:run -Dspring-boot.run.profiles=
)
```

Для фронтенда на порту 5173 укажите в `.env`
`CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173` и запускайте его как в разделе «Запуск».

Пустой профиль выключает `dev` и возвращает настройки из `application.yml`. Собранный jar и
docker образ и так идут в постгрес, профиль `dev` прописан только в maven-плагине для удобства

Если порт 5432 уже занят, контейнер не запустится на том же порту. Можно задать другой
`DB_PORT_HOST` в `.env` или использовать установленный PostgreSQL. Для второго варианта
при наличии прав создайте роль и базу:

```bash
psql -d postgres -c "CREATE ROLE tutor WITH LOGIN PASSWORD 'tutor' CREATEDB;"
createdb -O tutor tutorsite
```

В этом примере пароль роли — `tutor`: значение `DB_PASSWORD` должно совпадать с ним.
Если роль и база уже существуют, повторять создание не нужно. Для запуска от существующей
роли PostgreSQL, совпадающей с системным пользователем, из каталога `backend` можно использовать:

```bash
DB_USER="$(whoami)" DB_PASSWORD= ADMIN_PASSWORD=admin123 \
  mvn spring-boot:run -Dspring-boot.run.profiles=
```

Этот вариант подходит только если база `tutorsite` уже создана, роль имеет к ней доступ,
а настройки PostgreSQL допускают подключение без пароля. Пустой профиль обязателен:
без него Maven снова запустит H2, а не PostgreSQL.

### Всё в контейнерах

Создайте `.env`, если его ещё нет (не перезаписывайте существующий файл с настройками):

```bash
cp .env.example .env
```

Задайте `ADMIN_PASSWORD`, `JWT_SECRET` и `DB_PASSWORD`. Без первых двух Compose не стартует;
пустой `DB_PASSWORD` приведёт к использованию демонстрационного пароля `tutor`.
Ключ подписи удобно сгенерировать так:

```bash
openssl rand -base64 48
```

Затем поднимайте:

```bash
docker compose --profile full up --build -d
```

Фронтенд соберётся и будет доступен через nginx на http://localhost:3000, бэкенд и база
поднимутся рядом. Для этого адреса используйте `CORS_ORIGINS=http://localhost:3000`.
При смене адреса или порта добавьте фактический адрес сайта в `CORS_ORIGINS`.

## Развёртывание на тестовом сервере

Нужен только docker с плагином compose. Порядок:

```bash
git clone https://github.com/Vl1ko/ITMO-Physics-Site.git tutorsite && cd tutorsite
cp .env.example .env
```

Заполните `.env`: `ADMIN_PASSWORD`, `JWT_SECRET`, `DB_PASSWORD`. При необходимости смените
`WEB_PORT`, если 3000 уже занят. В `CORS_ORIGINS` укажите адрес сайта, например
`http://<адрес-сервера>:3000` или HTTPS-домен. При нескольких адресах разделяйте их запятыми.
Проксирование запросов не гарантирует обход проверки CORS. Дальше:

```bash
docker compose --profile full up --build -d
```

Первая сборка занимает несколько минут: Maven загружает зависимости, фронтенд собирается Vite.
Готовность видно по `docker compose --profile full ps`: у backend должен появиться статус `healthy`.
После этого запускается frontend. При ошибках смотрите `docker compose --profile full logs backend frontend`.

Сайт откроется на `http://<адрес-сервера>:3000`. Учётные записи для показа:

| Роль | Логин | Пароль |
|---|---|---|
| Админ | значение `ADMIN_EMAIL` | значение `ADMIN_PASSWORD` |
| Ученик | student@tutorsite.local | student |
| Ученик | petrova@tutorsite.local | student |

Демоданные заливаются один раз - только в пустую базу. На постгресе с томом `pgdata` это значит,
что менять `ADMIN_PASSWORD` после первого старта недостаточно: пользователь уже создан.
Для смены пароля в существующей базе нужно сохранить корректный BCrypt-хеш, а не открытый пароль.
Пересоздание базы допустимо только для ненужного тестового стенда, когда потеря всех данных согласована:

```bash
docker compose --profile full down -v && docker compose --profile full up --build -d
```

Флаг `-v` сносит том вместе со всеми данными - на боевой базе так делать нельзя.

### Обновить до свежего кода

```bash
git pull && docker compose --profile full up --build -d
```

Том с базой переживает пересборку. `ddl-auto: update` пытается обновить схему автоматически,
но не заменяет миграции и резервные копии: перед обновлением важных данных сделайте бэкап.

## Что умеет

Публичная часть - главная с отзывами, «Обо мне», «Исследования», контакты. Тексты двух страниц
правятся из админки визуальным редактором

Каталог задач - лента карточек с формулами в LaTeX (рендерит KaTeX), встроенными видео-разборами
и ссылками на PDF. Фильтры «предмет → класс → сложность → тема» работают без перезагрузки страницы:
на бэке это динамические Specifications, на фронте обычный fetch с перерисовкой ленты

Личный кабинет ученика - список назначенных заданий с дедлайнами, статусами и оценками, полоса
прогресса и форма отзыва. Отзыв не появляется на сайте сразу, а уходит на модерацию

Админка - таблица учеников (ФИО, класс, предмет, цели, оценки за ДЗ по 10-балльной шкале, прогресс,
заметки) с выгрузкой в xlsx, управление задачами с предпросмотром формул, модерация отзывов
и редактирование страниц

Роли три: гость, ученик и админ. Разграничение живёт и на бэке в Spring Security, и на фронте
в защищённых маршрутах. Доступ к административным и ученическим API проверяется на сервере.

## Проверки и сборка

Все команды ниже выполняются из корня проекта; скобки сохраняют текущий каталог терминала.

```bash
# Бэкенд: тесты и сборка JAR
(cd backend && mvn verify)

# Фронтенд: установка зависимостей, проверка типов, тесты и production-сборка
(cd frontend && npm ci && npm run typecheck && npm test && npm run build)
```

Результаты сборки: JAR в `backend/target/`, статические файлы в `frontend/dist/`.
Для полноценной работы фронтенду нужен запущенный бэкенд и прокси `/api`, как в Vite dev
или приложенном nginx-конфиге. Команда `npm run preview` сама по себе не поднимает API.
